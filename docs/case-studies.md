## 사례 1: WannaCry 랜섬웨어 (2017)

- 유형: 랜섬웨어 (자가 전파형, 웜 결합)
- 시기: 2017년 5월
- 감염경로 / 침투경로: Windows SMBv1 프로토콜의 취약점(EternalBlue, CVE-2017-0144)을 악용. 이 취약점은 원래 NSA가 보유하던 것이 유출되어 공개됨. DoublePulsar 백도어와 결합해 네트워크 내 다른 취약한 단말로 자동 확산.
- 공격 방법: 최초 침투 후 SMB 취약점을 통해 같은 네트워크 내 다른 PC로 자동 전파(웜 방식) → 파일 암호화 → 비트코인 몸값 요구
- 피해 규모: 150개국 이상, 20만 대 이상의 컴퓨터 감염. 영국 NHS(국민보건서비스), 스페인 텔레포니카, 페덱스, 르노 등 주요 기관 다수 피해.
- 알려진 사례(실제 사건): 위 규모 자체가 대표 사건. 보안 연구자 Marcus Hutchins가 악성코드에 포함된 도메인을 등록해 킬스위치를 작동시켜 확산을 저지한 것으로 유명.
- ATT&CK 매핑 단계: 초기 침투(Exploitation of Remote Services) → 횡적 이동(Lateral Movement, SMB 취약점 자동 확산) → 영향(Impact, 데이터 암호화)
- 관련 필요 지식: SMB 프로토콜, 패치 관리(패치가 이미 있었는데도 미적용 시스템이 대량 감염된 사례라 패치 관리의 중요성을 보여줌), 네트워크 세그멘테이션
- 방어 방법: SMBv1 비활성화, 네트워크 세그멘테이션으로 확산 범위 제한
- 예방 방법: 정기 패치 적용, 불필요한 SMB 포트(445) 외부 노출 차단
- 치료/대응 방법: 감염 단말 즉시 네트워크 격리, 백업을 통한 복구(몸값 지불은 권장되지 않음)
- 출처: CISA WannaCry 지표(cisa.gov), Wikipedia — WannaCry ransomware attack

## 사례 2: Mirai 봇넷의 Dyn DNS DDoS 공격 (2016)

- 유형: DDoS (IoT 봇넷 기반)
- 시기: 2016년 10월 21일
- 감염경로 / 침투경로: CCTV 카메라, DVR 등 IoT 기기의 기본/취약 관리자 계정(디폴트 아이디·비밀번호)을 스캔하여 무단 접속 후 Mirai 악성코드 감염
- 공격 방법: 감염된 대량의 IoT 기기로 봇넷을 구성하여 DNS 서비스 제공업체 Dyn에 대규모 트래픽(약 1.2Tbps 추정)을 집중시켜 서비스 불능 상태로 만듦
- 피해 규모: Dyn의 DNS 서비스 장애로 Twitter, Netflix, Reddit, GitHub, PayPal 등 미국/유럽 다수 주요 서비스가 장시간 접속 불가
- 알려진 사례(실제 사건): 위 사건 자체가 IoT 기반 DDoS의 대표 사례로 꼽힘
- ATT&CK 매핑 단계: 초기 침투(취약한 인증정보를 통한 접근) → 지속성(봇넷 유지) → 영향(가용성 침해, DDoS)
- 관련 필요 지식: DNS 인프라의 중요성(단일 DNS 제공업체 장애가 연쇄적으로 다수 서비스에 영향을 준 사례), IoT 기기 보안, 봇넷 개념
- 방어 방법: DDoS 방어 서비스(CDN, 스크러빙 센터) 활용, DNS 이중화
- 예방 방법: IoT 기기 기본 비밀번호 변경 의무화, 불필요한 원격 접속 포트 차단
- 치료/대응 방법: 트래픽 필터링, 업스트림 ISP와 협조한 트래픽 차단
- 출처: CISA Mirai 경보(cisa.gov), ThousandEyes 분석(thousandeyes.com)

## 사례 3: CSRF (Cross-Site Request Forgery) — 공격 기법 개념 정리

- 유형: 웹 애플리케이션 공격 기법 (특정 단일 사건이 아닌 기법 자체)
- 감염경로 / 침투경로: 사용자가 공격자가 만든 악성 페이지나 링크를 방문했을 때, 이미 로그인되어 있는 다른 사이트에 사용자 의도와 무관하게 요청이 자동 전송됨
- 공격 방법: 피해자의 인증 세션(쿠키 등)을 이용해 피해자 모르게 상태 변경 요청(비밀번호 변경, 송금, 설정 변경 등)을 대신 전송
- 관련 필요 지식: 쿠키 기반 세션 인증의 동작 원리, Same-Origin Policy, CSRF 토큰 개념
- 방어 방법: CSRF 토큰 검증, SameSite 쿠키 속성 설정, Referer/Origin 헤더 검증
- 예방 방법: 상태 변경 요청에는 항상 CSRF 토큰 요구, 중요 작업은 재인증 요구
- 참고: 이 프로젝트의 서버(중앙 관리 서버) 구축 시 관리자 웹 콘솔이 있다면 직접 관련되는 취약점이므로 우선순위 높게 학습

## 사용 방법
- 새 사례를 학습할 때마다 위 템플릿으로 이 문서 하단에 추가
- 최소 목표: 랜섬웨어 2~3건, DDoS 2건, CSRF 등 웹 공격 기법 2~3건, 기타(피싱, 내부자 위협 등) 수집
- 트랙 C(기존 보안 기술 조사)에서 도구를 볼 때, 어떤 사례를 막기 위한 기능인지 이 문서와 연결해서 정리하면 이해가 빨라짐

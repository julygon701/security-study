# 학습 기록 (트랙 A — OS/네트워크 기초)

트랙 A 학습 진행 중 정리한 내용을 날짜순으로 기록한다. 새로 공부한 날마다 아래에 날짜 섹션을 추가한다.

## 기록 방식
각 날짜 섹션은 아래 3부분으로 구성한다.

1. **학습 내용 정리** — 그날 공부한 내용을 정리한 본문
2. **부연 설명** — 이해를 넓히는 배경·맥락, 그리고 프로젝트와 연결되는 지점
3. **정정 사항** — 처음 이해가 부정확했던 부분을 별도로 분리해 기록. 무엇을 어떻게 이해했었고 실제로는 무엇인지를 함께 남긴다. 잘못 이해한 내용이 그대로 설계에 반영되는 것을 막고, 나중에 다시 볼 때 이해의 변화를 추적하기 위함이다.

## 2026-08-21 — OSI 7계층과 식별자, IP 주소 체계

### 계층별 식별자
각 계층은 "무엇을 구분하기 위한" 고유한 식별자를 가진다. 어떤 대상에 대한 식별자인지를 함께 기억하는 것이 중요하다.

| 계층 | 식별자 | 무엇에 대한 식별자인가 |
|---|---|---|
| L4 (전송) | Port 번호 | 관점에 따라 다름 (아래 참고) |
| L3 (네트워크) | IP 주소 | Host (인터넷에 연결된 컴퓨터) |
| L2 (데이터링크) | MAC 주소 | NIC (Network Interface Card, 유·무선 랜카드) |

### MAC 주소와 IP 주소의 차이
- MAC 주소는 랜카드(NIC)라는 하드웨어 부품에 부여된 식별자이므로 자주 변경되지 않는다. 다만 하드웨어 부품임에도 소프트웨어적으로 변경(MAC 스푸핑)은 가능하다.
- IP 주소는 하나의 NIC에 여러 개를 바인딩해서 사용할 수 있다. 즉 컴퓨터당 IP 주소는 n개 존재할 수 있다.
- MAC 주소는 NIC마다 하나씩 부여된다.

### Port 번호에 대한 관점 차이
같은 포트 번호를 두고도 직무에 따라 다르게 인식한다. 이 차이를 알아야 다른 직군과 대화할 때 혼선이 없다.

- **S/W 개발자**: 프로세스(process) 식별자로 인식
- **네트워크 관리자** (L4 업무 위주): 서비스(service) 식별자로 인식
- **H/W 관리자** (네트워크 통신 장비를 직접 설치하는 사람): 인터페이스 번호로 인식 (스위치·랜에 꽂는 단자 번호 같은 개념)

### IP (Internet Protocol)
IP는 "인터넷 규약"을 의미한다.

**종류**
- IPv4 — 32bit. 8bit씩 끊어서 4개의 숫자로 표기 (예: 192.168.60.14)
- IPv6 — 128bit

**Net ID와 Host ID (IPv4 기준)**
IP 주소는 "어느 네트워크인가(Net ID)"와 "그 네트워크 안의 어느 장비인가(Host ID)"로 나뉜다.
- C 클래스 기준: 앞 3자리가 Net ID, 뒤 1자리가 Host ID

**서브넷 마스크**
IP 주소에서 Net ID의 길이를 나타내는 값. IP 주소와 서브넷 마스크를 비트 연산(AND)하면 Net ID를 구할 수 있다.

예시:
```
IP 주소      : 192.168.60.14
서브넷 마스크 : 255.255.255.0
→ AND 연산 결과
   Net ID  : 192.168.60.0
   Host ID : 14
```

**CIDR 표기법 (Classless Inter-Domain Routing)**
서브넷 마스크를 슬래시와 비트 수로 간략히 표기하는 방식.
```
192.168.60.14/24
```
`/24`는 앞 24비트(= 255.255.255.0)가 Net ID라는 의미다.

### 부연 설명
- 서브넷 마스크의 AND 연산은 직접 2진수로 바꿔 계산해보면 이해가 빠르다. 예: `60`(10진수) = `00111100`(2진수), `255` = `11111111` → AND 결과는 그대로 `00111100`. 반대로 마스크가 `0`인 자리는 결과가 전부 `0`이 되므로, 마스크의 `1` 부분만 살아남아 Net ID가 된다.
- CIDR의 "Classless"는 기존의 클래스(A/B/C) 구분에 얽매이지 않는다는 뜻이다. 클래스 방식은 Net ID 길이가 8/16/24비트로 고정이었지만, CIDR은 `/26`, `/30` 같은 임의의 길이를 쓸 수 있어 IP 주소를 훨씬 유연하게 나눠 쓸 수 있다.

### 정정 사항
> 처음 정리한 내용 중 부정확했던 부분.

- **"MAC은 컴퓨터당 1개"** → 정확히는 **NIC당 1개**. 유선 랜카드와 무선 랜카드가 모두 있는 노트북은 MAC 주소를 2개 이상 가진다.
- **"L1, L2 : MAC"** → MAC은 정확히 **L2(데이터링크 계층)의 식별자**다. L1(물리 계층)은 전기 신호·케이블 등을 다루는 계층이라 주소 개념 자체가 없다.

### 프로젝트와의 연결점
- **단말 고유 ID 설계**: MAC 주소를 단말 식별의 기준으로 삼으면, 같은 노트북이 유선에서 무선으로 연결을 바꾸는 순간 다른 장비로 인식된다. 사내에 랜선으로 연결하는 개인 노트북이 있으므로 실제로 부딪힐 문제다. MAC 단독이 아닌 별도 ID 체계가 필요하다.
- **네트워크 격리**: 감염 단말을 격리할 때 "같은 Net ID 안에 있는 장비들"이 곧 1차 확산 위험 범위가 된다. 서브넷 개념이 트랙 C에서 다룰 네트워크 세그멘테이션·VLAN 격리 설계의 기초가 된다.
